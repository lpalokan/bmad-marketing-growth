# Integrated GTM Plan

<instructions>
Produce a single go-to-market plan that aligns the marketing wing's bets
and the sales wing's account motion on the same targets, the same
narrative, and the same measurement. This is a sequencing document — it
names which orchestrator runs what, in what order, with which handoffs —
not a substitute for their domain plans.
</instructions>

<process>
1. Ground the plan (Source Fidelity applies):
   - Read what exists in `{output_folder}/company-context/`: `icp.md`,
     `positioning.md`, `kpis.md`, `offerings.md`, `icp-fit-model.md`,
     `signal-library.md`.
   - Ask focused questions for what's missing and load-bearing: revenue
     target or pipeline goal, sales capacity (who works the accounts),
     marketing budget envelope, planning horizon (quarter or year).
2. Define the shared target picture:
   - Which segments/accounts both wings aim at. If no tiered target list
     exists, the first play in the plan is Sam Sell briefing Tara Target
     (source-accounts) — do not invent a list.
   - The one account narrative both wings will tell (existing
     `positioning.md` + Stella Story / Pierce Pitch storyline work if it
     exists).
3. Lay out the motion as 3–5 sequenced plays, each with:
   - **Owner** — the orchestrator or workflow that runs it (org chart in
     `SKILL.md`).
   - **Contribution** — what it produces and which wing consumes it
     (e.g. `abm-program` warms Tier-A accounts → Sam's motion picks the
     warmed accounts; Sage Signal's triggers → Dani Demand retargeting).
   - **Timing** relative to the other plays.
   - **Handoff** — the artifact that crosses the wing boundary, and
     where it lives under `{output_folder}/work/`.
4. Measurement: one shared funnel definition with Pixel Metrics
   (`growth-analyst`) named as the owner of attribution across both
   wings. KPIs come from `kpis.md` or from the user — never invented.
5. Write the plan to
   `{output_folder}/work/{yyyy}-{qN}-gtm-plan/gtm-plan.md`, then walk the
   user through the play sequence and the first concrete next step
   (usually: activate the first play's owner).
</process>
